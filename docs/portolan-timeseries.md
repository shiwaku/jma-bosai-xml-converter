# メモ: Portolan のカタログで時系列を扱えるか（2026年11月27日）

**結論: 時系列は扱える。ただし「常に最新」を出すリアルタイム用途には向かない。** 以前に確認した Portolan の仕様（STAC 1.1 の静的カタログ。GeoParquet・PMTiles・COG）にもとづく整理で、最新版は未確認。Portolan への掲載は保留中で、再開するときに最新の仕様を確認する。

## 「時系列」の3つの意味

| 時系列の種類 | Portolan で扱えるか | 方法 |
|---|---|---|
| **1通の電文の中の予報時刻**（今日・明日・3時間ごとなど） | できる | 時刻の列を持つ縦長の GeoParquet にする。[府県天気予報の検証](verification-forecast.md)で作った `forecast_long.parquet` がこの形 |
| **電文の積み重ね**（発表ごとの予報、10分ごとの警報） | できる。向いている | 日ごとに分けた GeoParquet を、日時（`datetime`、または `start_datetime` / `end_datetime`）つきの STAC Item として登録する。過去の電文を1日分ずつ置く使い方は、静的なカタログに合う |
| **常に最新**（いま警報が出ている所） | 向かない | Portolan は「データを公開してからカタログに載せる」仕組みで、10分ごとにファイルを書き換える使い方を想定していない |

## 補足

- **PMTiles には時間の軸がない。** 地図で時刻を切り替えるには、各時刻の値をタイルの属性に持たせる（府県天気予報の検証の地図と同じやり方）か、時刻ごとに別のタイルを作る。
- **境界（形）と値は分けて持つ。** 予報区等GISデータの形はめったに変わらないので1つだけ置き、時刻ごとに変わる値は縦長の表にして、地域コードで結合する。

## 役割の分け方（案）

- **Portolan（shi-works-catalog の `jp-jma/`）**: 予報区等GISデータの形と、過去の電文を変換した日ごとのアーカイブ
- **最新の状態**: MCP サーバー（別リポジトリ）か、定期的に上書きするファイル
